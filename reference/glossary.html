System Design · Reference

Glossary

The canonical language for this workspace. Grows as you master terms — not a dictionary to read cold.

This glossary starts with the delivery-framework vocabulary from Lesson 01. As you demonstrate understanding of new concepts (caching, sharding, CAP…), we promote them here with tight, opinionated definitions you can lean on in every future design.

Delivery Framework

Functional Requirement (FR)
A capability the system must give users, phrased "users should be able to…". Aim for 3 core ones. Avoid: feature, user story
Non-Functional Requirement (NFR)
A quality the system must have rather than a feature it must do — latency, availability, consistency, durability, scalability. The "-ilities". Aim for 3–5. Avoid: constraints, the -ilities (informally)
Core Entity
A primary noun the system stores and reasons about (User, Ride, Paste). The seed of your data model. Avoid: object, model, table
High-Level Design (HLD)
The boxes-and-arrows architecture: components and how a request flows between them, kept deliberately shallow on the first pass. Avoid: architecture diagram, the design
Deep Dive
Focused exploration of one hard part of the design to meet an NFR or kill a bottleneck. Where the L6/L7 hour is mostly spent. Avoid: detail, follow-up
Capacity Estimation
Back-of-envelope math (QPS, storage, bandwidth) done only when the number changes a design decision. Avoid: sizing, the math

Interview Calibration

Breadth / Depth ratio
How interview time is split between covering the whole system vs. drilling into parts. Mid 80/20, Senior 60/40, Staff (L6/L7) 40/60.
Staff signal
Behaviors that read as staff+, not senior: simple-by-default designs, proactive deep dives, clear judgement on alternatives, and not over-explaining basic concepts.

Vector Search (Lesson 40)

Embedding
A fixed-length array of floats produced by a model (LLM, CLIP, sentence-transformer) where semantic closeness becomes geometric closeness. The unit a vector DB stores. Avoid: vector (loosely), feature array
Approximate Nearest Neighbor (ANN)
Search that returns most of the true k closest vectors quickly, trading a little accuracy for orders-of-magnitude speed over the O(N·D) exact scan. Avoid: similarity search (too vague)
HNSW
Hierarchical Navigable Small World — the dominant ANN index: a multi-layer graph searched by greedy descent. O(log N) search, 99%+ recall. ef_search is its recall-vs-latency knob. Avoid: "the graph index"
Recall
The fraction of the true nearest neighbors an ANN query actually returned. The accuracy axis traded against latency. Avoid: accuracy (imprecise)
Quantization (PQ)
Lossy compression of vectors into compact codes (Product/Scalar Quantization) to fit billions of them in RAM, at a small recall cost. Avoid: compression (generic)

Big-Data Structures (Lesson 41)

Probabilistic Data Structure (PDS)
A hash-based structure that answers a question approximately with a bounded, predictable error in tiny fixed memory. Pick it by the question and the acceptable error direction. Avoid: sketch (only some are)
Bloom filter
Set-membership test with zero false negatives, only false positives. "No" = definitely absent; "yes" = probably present. Avoid: hash set, dedup cache
HyperLogLog (HLL)
Cardinality (count-distinct) estimator: ~12 KB fixed, ±0.81% error, for billions of items; mergeable across shards. Avoid: unique counter
Count-Min Sketch (CMS)
Frequency / heavy-hitter estimator on a counter matrix; over-counts but never under-counts. Pair with a min-heap for top-K. Avoid: frequency table

Time-Series (Lesson 42)

Cardinality
The number of unique (metric name, label set) series — the primary scaling constraint of a TSDB. One unbounded label (user_id, request_id) explodes it. Avoid: volume, row count
Downsampling
Rolling raw points into coarser pre-aggregated tiers (raw → 1m → 1h) so long-range queries stay cheap. The economic foundation of long retention. Avoid: aggregation (generic), sampling
Gorilla compression
Delta-of-delta on timestamps + XOR on float values → ~1.3 bytes/sample from a naïve 16. What makes TSDB storage affordable. Avoid: "compression"

Storage Engines & Datastores (Lessons 88–98, 114)

B-tree
Read-optimized storage engine: sorted pages, in-place updates, ~3–4 seeks per lookup. Powers Postgres/MySQL. Avoid: just "index"
LSM-tree
Write-optimized engine: appends to an in-memory memtable, flushed sequentially to immutable SSTables, merged by compaction. Powers Cassandra/RocksDB. Avoid: log
Write/read amplification
The core engine trade-off: B-trees minimize read amplification (random-I/O writes), LSM-trees minimize write amplification at ingest (multi-file reads + compaction).
MVCC
Multi-version concurrency control: keep row versions so readers see a consistent snapshot and don't block writers (or vice versa). Avoid: locking
Write-ahead log (WAL)
Append the change to a sequential log (and fsync) before touching data pages; replay on recovery gives durability + crash safety.
Index-free adjacency
Graph-DB property where relationships are direct pointers, making each traversal hop O(degree) instead of an index join. Why Neo4j beats SQL for deep traversals.

Messaging, Streaming & Coordination (Lessons 99–108)

Partition (Kafka)
The unit of parallelism and ordering in a log; order is guaranteed only within a partition, and the key chooses the partition. Avoid: shard
Watermark
A stream-processing marker asserting "no more events older than time T," letting windows close despite out-of-order/late events (Flink). Avoid: timestamp
Shuffle
The expensive cross-network repartition between stages in Spark/MapReduce (a wide dependency); minimizing it is the main tuning lever.
Consensus
Getting N nodes to agree on one value/log order despite crashes, via a majority quorum (Raft, Paxos). Underpins etcd/ZK, Spanner. Avoid: 2PC
Gossip protocol
Epidemic dissemination: each node periodically swaps state with random peers; converges in O(log N) rounds. Used for membership/failure detection (Cassandra).
Reconciliation loop
Kubernetes' core pattern: controllers continuously drive actual state toward the declared desired state stored in etcd. Avoid: orchestration

Cross-Cutting (Lessons 109–119)

Idempotency key
A client-supplied unique id on a write so a retried request returns the original result instead of repeating the effect. Essential for payments.
Cursor pagination
Keyset paging anchored to the last item seen (WHERE id < cursor); stable under writes and index-friendly at any depth, unlike offset.
Saga
A sequence of local transactions with compensating actions, trading isolation for availability across services. Default for distributed transactions. Avoid: 2PC
Change Data Capture (CDC)
Streaming row-level DB changes (usually off the WAL) to keep derived stores in sync; cures the dual-write bug. Avoid: replication (generic)
Fencing token
A monotonically increasing number issued with a distributed lock; the resource rejects writes carrying a stale token, making locks safe under pauses.
Geohash
Encoding of lat/lng into a base-32 string where a longer shared prefix means closer points, turning proximity into an indexable prefix query. Query the 8 neighbors too.
JWT
Signed, self-contained token (header.payload.signature) verified locally without a DB lookup; stateless but hard to revoke (use short TTL + refresh).

Real-Time, Networking & Reliability (Lessons 120–122)

WebSocket
A persistent, full-duplex TCP connection over a single upgraded HTTP request; both sides push anytime. The default for chat/collab. Avoid: socket
Server-Sent Events (SSE)
A one-way server→client stream over a long-lived HTTP response; simpler than WebSockets and ideal for feeds/notifications that don't need client→server push.
Long polling
The client holds a request open until the server has data, then immediately re-requests; emulates push over plain HTTP at the cost of overhead and latency.
Backplane (pub/sub fan-out)
A shared bus (often Redis pub/sub) that routes a message to whichever server holds the target user's live connection, so real-time delivery scales past one node.
L4 vs L7 load balancing
L4 routes by IP/port (fast, content-blind); L7 routes by URL/header/cookie and can terminate TLS (smarter, costlier). WebSockets typically need L4 + stickiness.
Delivery semantics
At-most-once (may drop), at-least-once (may duplicate), exactly-once (neither). True exactly-once delivery is impossible; aim for "effectively-once" = at-least-once delivery + idempotent processing. Avoid: exactly-once (loosely)
